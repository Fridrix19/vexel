# Бэкенд Vexel

Nuxt 4 + Nitro, PostgreSQL 16. Сервер отдаёт прототип (`../_proto`) как статику и API по `/api/*`.
Страницы `login.html` и `dashboard.html` сами проверяют `/api/health`: есть сервер — работают с настоящими данными, нет (Vercel, артефакт, file://) — в демо-режиме.

## Запуск

```bash
cd web
npm ci
export NUXT_DATABASE_URL=postgres://…   # или DATABASE_URL
export NUXT_SECRET=$(openssl rand -hex 32)
npm run migrate          # применяет server/db/migrations/*.sql, повторный запуск ничего не меняет
npm run build && npm start   # или npm run dev
```

Переменные окружения:

| переменная | по умолчанию | что это |
|---|---|---|
| `NUXT_DATABASE_URL` | — | строка подключения (Neon: `…?sslmode=require`) |
| `NUXT_SECRET` | — (в проде обязателен) | HMAC кодов из писем и ключ AES-GCM для данных выдачи. Не менять после запуска |
| `NUXT_MAIL_PROVIDER` | `log` | `log` — письма в консоль; `unisender` — Unisender Go |
| `NUXT_UNISENDER_KEY`, `NUXT_UNISENDER_URL` | —, `go1…/api/v1` | ключ и адрес API из кабинета Unisender Go |
| `NUXT_MAIL_FROM` | `noreply@vexel.ru` | отправитель (домен с SPF/DKIM) |
| `NUXT_PAYMENT_PROVIDER` | `test` | пока только тестовый провайдер |
| `NUXT_COOKIE_SECURE` | `false` | `true` за HTTPS |
| `NUXT_DEV_CODES` | `false` | `true` только на стенде: код показывается на экране, **но только пока почта в режиме log** — с Unisender коды приходят только письмом |
| `NUXT_PUBLIC_SITE_URL` | — | адрес сайта для ссылок в письмах |
| `NUXT_ADMIN_NOTIFY_EMAIL` | — | куда слать о новых заказах, KYC и возвратах |

Деплой на Render — `render.yaml` в корне репозитория (миграции запускаются при старте).

## Тесты

```bash
NUXT_SECRET=x NUXT_DATABASE_URL=… NUXT_DEV_CODES=true PORT=3100 node .output/server/index.mjs &
DATABASE_URL=… API_URL=http://localhost:3100 npm test
```

Покрыто: регистрация (код до создания аккаунта, занятая почта, попытки кода), вход и блокировка после 5 ошибок, вход по коду, сброс пароля с завершением сессий, профиль, сессии, смена пароля, загрузка KYC, пополнение и повтор вебхука, KYC-запрет покупки, недостача с суммой, идемпотентная покупка, пополнение «под заказ», карта с произвольной суммой, каталог.

## API

Ошибки: `{ statusCode, message, data: { code, … } }` — `message` можно показывать пользователю.

| метод | путь | что делает |
|---|---|---|
| POST | `/api/auth/register/start` | `{email, username}` → код на почту; почта только с разрешённых доменов (`email_domain`), `409 email_taken` / `username_taken` |
| GET | `/api/auth/username-check?u=` | свободен ли логин |
| POST | `/api/auth/register/complete` | `{email, username, code, password, agree, news}` → аккаунт + сессия |
| POST | `/api/auth/login` | `{login, password}` — логин или почта; 5 ошибок — `429 locked` на 15 минут |
| POST | `/api/auth/login/code-start`, `/api/auth/login/code` | вход по коду из письма |
| POST | `/api/auth/reset/start` → `/reset/check` → `/reset/complete` | `{login}` (логин или почта) → письмо со ссылкой `login.html#reset:<токен>` (30 минут, один раз) → новый пароль, все сессии завершаются |
| POST | `/api/auth/logout` · GET `/api/auth/me` | выход · профиль с балансом |
| GET/DELETE | `/api/auth/sessions`, `/api/auth/sessions/:id` (`others`) | устройства |
| POST | `/api/auth/password` | `{old, new}`, остальные сессии завершаются |
| PATCH | `/api/profile` | `{name, phone, telegram}` — Telegram: `@имя`, `t.me/имя` или пусто |
| GET/POST | `/api/kyc` | статус · загрузка фото (multipart `files`, 1–4 шт., JPG/PNG/HEIC/PDF до 10 МБ) |
| GET | `/api/catalog`, `/api/catalog/:slug` | разделы, товары, тарифы с итоговой ценой в копейках |
| GET | `/api/balance` | баланс и журнал операций |
| POST | `/api/topups` | `{amount_kop, for_order?}` → платёж; `for_order` — оформить заказ сразу после оплаты |
| POST | `/api/topups/:id/test` | тестовый провайдер: `{action: succeed|cancel}` (в бою выключен) |
| GET | `/api/topups/:id`, `/api/payments` | статус платежа, история пополнений |
| POST | `/api/orders` | `{plan_id, fields, amount_cents?, idem, gift_to?, use_bonus?}` → заказ с баланса (бонус по умолчанию списывается скидкой); `403 limit_exceeded` + `remaining_kop, limit_kop, resets_at`, `402 insufficient_funds` + `shortfall_kop`, `409 docs_update_required` — сначала принять новую редакцию документов. `gift_to` — подарок: карта перейдёт другу при входе с этой почтой |
| GET | `/api/orders`, `/api/orders/:id` | заказы, карточка с событиями и выдачей |
| GET/POST | `/api/notifications`, `/api/notifications/read` | уведомления |
| GET | `/api/site` | контакты (почта, Telegram, Max) и действующие документы — для сайта |
| GET/POST | `/api/me/documents` | действующие редакции (принята ли и когда) и история согласий · принять `{ids?}` |
| GET/POST | `/api/reviews` (`?product=slug`, без — все) | отзывы · `{order_id, rating 1–5, text, author}` — по исполненному заказу, повтор — правка |
| GET/POST/DELETE | `/api/favorites`, `/api/favorites/:slug` | избранное |
| GET | `/api/chats`, `/api/chats/thread?order=&after=` | ветки чата (общая и по заказам), сообщения с id > after |
| POST | `/api/chats/send` | `{text, order_id?}` или multipart с `file` (JPG/PNG/WebP/PDF до 10 МБ) |
| POST | `/api/t` | события поведения `{a: id браузера, s: визит, r: referrer, e: [{t: view/leave/click, p, tg, l, d, sp}]}`, ответ 204 |

## Админка — `/admin`

Nuxt-страницы на PrimeVue 4.5 с пресетом Vexel (`app/theme/vexel.ts` — тот же объект, что в дизайн-системе). API — `/api/admin/*`, отдельная кука `mc_adm` (12 часов, SameSite=Strict).

Первый вход: **admin / admin** — `npm run migrate` создаёт владельца, если админов нет (пароль можно задать `ADMIN_BOOTSTRAP_PASSWORD`, отключить — `ADMIN_BOOTSTRAP=off`). После входа админка требует сменить пароль.

| раздел | что делает | роли |
|---|---|---|
| Сводка | очереди; за выбранный период — продажи, заказы, покупатели, пополнения, возвраты, новые пользователи, KYC, посетители; график, топ товаров, заканчивающиеся ключи | все |
| Чаты | очередь «ждут ответа» как в мессенджере, переписка, вложения, закрыть/открыть; клиенту — уведомление | владелец, старший, оператор |
| Отзывы | скрыть/показать, ответ магазина | владелец, старший, оператор |
| Аналитика | посетители (и без аккаунта), визиты, время на страницах, прокрутка, клики, источники, устройства, воронка; история действий пользователя по логину или почте | владелец, старший |
| Заказы | поиск, фильтры, карточка: данные покупателя, история, выдача вручную (шифруется) или ключ из пула, «В работу», «Нужны данные» (уведомление клиенту), возврат на баланс | владелец, оператор |
| Верификация | очередь, просмотр фото, одобрить (с датой рождения) / отклонить с причиной, переход к следующей заявке | все |
| Возвраты | заявки клиентов: на баланс — сразу; на карту — одобрить → вернуть у провайдера → «Отправлено» | владелец, оператор |
| Пользователи | поиск, баланс и журнал, заказы, пополнения, карты, сессии, блокировка с причиной, начисление/списание с комментарием | корректировка — владелец |
| Товары и цены | раздел, описание, иконка, тип выдачи, поля покупателя, своя комиссия, активен/архив; тарифы в $ или ₽, диапазон суммы; пул ключей; курс ₽/$ | правка — владелец |
| Выгрузки CSV | заказы, пополнения, журнал баланса, пользователи за период | владелец, оператор |
| Админы | создание с временным паролем, роли и их права, кто и когда назначил, отключение, сброс пароля | владелец |
| Журнал действий | действия админов, входы и неудачные попытки, фильтр по админу и периоду. Владелец видит всех, старший — операторов, модераторов и себя | владелец, старший |
| Настройки | домены почты, контакты сайта, новые редакции оферты/политики/тарифов (PDF или ссылка), диагностика почты | владелец |

Роли: **владелец** — всё; **старший админ** — всё, кроме админов, настроек и правки товаров, плюс журнал младших и аналитика; **оператор** — заказы, возвраты, пользователи; **модератор KYC** — верификация. Заказы, верификация и возвраты фильтруются по периоду, у товаров видно, кто и когда правил последним.

Лимит расходов: без верификации — 15 000 ₽ за месяц, отсчёт с первой покупки (`users.limit_since`, `spend_state()`), через месяц следующая покупка открывает новый период; возвраты возвращают лимит; после верификации — без лимита (настраивается в «Настройках»). Бонус: за одобренную верификацию 500 ₽ один раз (`bonus_entries`, `user_bonus()`), при следующей оплате списывается скидкой целиком, остаток сгорает, при возврате заказа возвращается. В списке пользователей — шкала лимита и дата обновления, в карточке — бонусы, начисление/списание, досрочное обнуление периода.

Документы: действующая редакция — последняя опубликованная. После публикации всем приходит уведомление, перед следующей покупкой кабинет просит принять новую редакцию, дата согласия сохраняется (`user_consents`). Подарок: получатель без аккаунта получит письмо, карта ждёт его и переходит в кабинет при первом входе с этой почтой.

Сайт берёт цены, скрытые и новые товары из `/api/catalog` при каждом открытии страницы (`syncCatalog` в common.js, `service.js`, `MC.vcPricing`). Товар, добавленный в админке, открывается по `/service/<slug>/` — общая страница `_proto/service/_new/` заполняется из API. Курс — вручную или по ЦБ с наценкой (обновляется раз в 3 часа, `server/plugins/rate.ts`). Письма клиенту: заказ выполнен, нужны данные, решение по KYC и возврату; команде (`NUXT_ADMIN_NOTIFY_EMAIL`): новый заказ с ручной выдачей, закончились ключи, новая KYC-заявка, заявка на возврат. Возврат заказа виртуальной карты сначала списывает сумму с карты.

Новая цена тарифа действует только для новых заказов: в заказе хранится снимок цены и курса. Вход: 5 неудачных попыток с одного IP — пауза 15 минут. 2FA для админов — следующий шаг.

## Деньги

Баланс не хранится полем — это последняя проводка в `ledger_entries`. Любое движение денег идёт только через функции из `003_money.sql` / `004_auth_cards.sql`:

| функция | что делает |
|---|---|
| `user_balance(user)` | баланс в копейках |
| `payment_succeeded(payment)` | зачисляет пополнение; повторный вебхук ничего не меняет |
| `place_order(user, plan, fields, idem, amount_cents)` | проверяет KYC и баланс, фиксирует цену и курс, создаёт заказ `VX-XXXXXXXX` и списывает деньги одной транзакцией; `amount_cents` — для тарифа с произвольной суммой (карта $50–$200) |
| `refund_order(order, admin, reason)` | возврат на баланс, идемпотентно |
| `charged_cents(cents)` | комиссия сайта: до $45 — (сумма + 5) × 1.2, выше — × 1.3 |

`002_catalog.sql` генерируется `python3 build/seed_catalog.py` из тех же источников, что и прототип (139 товаров, 389 тарифов, цены 1:1 с исходным сайтом). `004` добавляет виртуальную карту как товар (номиналы 50/75/100/150/200 и своя сумма).
